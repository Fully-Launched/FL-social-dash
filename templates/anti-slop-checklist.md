# Anti-slop checklist

Shared by `voice-doc`, `customer-data-doc`, `positioning-doc`, and any skill
that authors even one sentence of prose (the one summary paragraph in a
Voice doc, a script line, a concept's hook). Adapted from a reference skill
Tait was given directly and asked to build toward — the discipline is
proven, so it lives here once instead of getting rewritten slightly
differently in every skill that needs it.

**One bounded exception**: `customer-data-doc`'s Pass 2 (industry research
plus inference from a client's own material) is deliberately generative —
Tait asked for that step directly. It still isn't exempt from rules 4-8
below (no em dashes, no fabricated proof, specific over generic, a stated
basis for every line), and it lives in a visibly separate "unconfirmed"
section that Tait reviews before anything in it counts as real. Nothing
else in this repo gets that exception.

## The inviolable rules

These cannot be overridden by a single request, a deadline, or a client who
wants it faster.

1. **The artifact is the source.** Write from the transcript, voice memo, or
   note actually given. If a claim, story, or number isn't in it, it doesn't
   go in the document. When the material can't answer what's needed, say so
   — see the refusal template below — never fill the gap with something
   plausible.
2. **Their words win.** Use real phrasing verbatim wherever it fits. Pull
   their language before reaching for a smoother version of it. This is
   transcription and organization, not a rewrite into someone more polished.
3. **Organize and amplify, never generate.** The job is finding the best of
   what's already there and making it legible — a categorized quote, a
   labeled pattern. If a line reads like an invented take the client never
   expressed, stop and cut it.
4. **No em dashes. Ever.** Use commas, periods, or parentheses.
5. **No "It's not X, it's Y."** Never negate one framing to assert another —
   that reframe is the single clearest sign a machine wrote it. Just say
   the thing.
6. **No AI tells.** Never use: delve, unlock, leverage, harness, seamless,
   robust, elevate, streamline, tapestry, realm, foster, supercharge,
   game-changing, resonate, pivotal, crucial, testament. Reach for a
   concrete verb instead: build, ship, run, cut, install.
7. **No fabricated proof.** Never invent a quote, a stat, a testimonial, or
   a result. If proof would help and isn't there, say what's missing rather
   than inventing it.
8. **Specific beats generic, always.** Real names, real numbers, real
   scenes from the material. Never "imagine a world where."

These rules govern the one place in each of these three skills where prose
actually gets authored (a summary paragraph, a distilled profile field).
They have nothing to do with the verbatim sections — a direct quote is
correct by definition, it doesn't need a taste pass.

## The taste pass

Before delivering any authored sentence (not a verbatim quote), check:

1. Does this sound like the person on the transcript reading it aloud, or
   like a brand?
2. Zero AI tells, zero em dashes, zero "It's not X, it's Y"?
3. Is every claim traceable to the material, with nothing invented?
4. One clear idea per line — not three hedges stacked into one sentence?

If any answer is no, rewrite before showing it.

## The refusal template

When a document needs something the uploaded material doesn't contain, say
exactly this rather than guessing:

> This isn't in the material uploaded for this client yet. To fill this in
> well, the actual raw input is needed — a transcript, a voice memo, a call
> note, real customer language. Once that's in the Inbox, this section
> updates from it, not before.

## Done means

- [ ] Every load-bearing line traces to a real, dated source
- [ ] Every authored sentence (not a quote) passes the taste pass
- [ ] Zero em dashes, zero AI tells, zero "It's not X, it's Y" anywhere in
      this document, including in prior sections from earlier runs
- [ ] Nothing invented to fill a gap — gaps are flagged, not smoothed over
- [ ] Verbatim material is actually verbatim — spot-check a few quotes
      against the source file before calling it done
